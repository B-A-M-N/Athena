# Athena terminal frontend (development preview)

This directory contains the first native frontend boundary for the Athena
terminal application. It is not a second agent runtime and it is not a copy of
the Python CLI.

The frontend tracks the upstream Alacritty terminal engine for PTY and parsing
semantics. An
Athena-owned compositor adds the reference-space graphite instrument chassis,
distinct flat operator and rounded Glass Compute wells, central divider,
physical lower control deck, and OpenGL OI scene. Structured projections drive
a semantic 384×256 DAGOAL world with contextual pixel information, task-object
continuity, Buddy pose changes, verification gates, and non-modal attention
overlays. The compositor consumes the shared projection contracts from
`src/athena/cli/` through a semantic bridge rather than reimplementing task
semantics.

The first native vertical slice now exists as `athena-terminal`. It owns a PTY,
feeds output through the pinned Alacritty terminal core, renders its
`RenderableContent` cells with Fontconfig/Xft, accepts UTF-8/IME keyboard input,
focus and resize events in its Linux/X11 window path, and consumes semantic
JSON projection frames without taking authority over Athena state. Projection
frames carry structured scene entities, model-request identity,
workspace/runtime trees, diagnostics, alerts, and attention items as well as
terminal text; the OpenGL compositor renders them as an AthenaBOX chassis,
deep-bezel displays, semantic OI view, and a quantized Buddy. Mouse selection,
Ctrl-Shift-C/Ctrl-Shift-V clipboard round-trips, scrollback, navigation keys,
and explicit prompt states are supported. The lower prompt is a Rust-owned
Unicode line editor and the PTY receives only completed lines. Ctrl-C cancels
the foreground task without closing the session; `/exit` closes it. Projection
schema 3 carries current action/query/progress context, while schema 2 is
normalized and unknown schemas are rendered as bridge errors. Font-derived
metrics are the source of truth for layout, text, hit testing, and PTY size;
motion-only OI updates use a retained dirty region. The canonical cabinet
design space is 1672×941 and is uniformly scaled with letterboxing. Static
cabinet engraving is rendered as a clipped bitmap design layer; only the
transcript, prompt, status, and other live text use Xft. Xft roles use
scale-aware pixel sizes and are reopened on live resize when their quantized
size changes. The borderless window has 12-pixel edge/corner resize zones with
directional cursors, plus header-fascia drag.

For a headless PTY/core/bridge smoke check:

```bash
cargo run --manifest-path native/Cargo.toml --offline -- \
  --headless --bridge-stdin --command 'printf "native-ok\\n"'
```

For the native window:

```bash
cargo build --manifest-path native/Cargo.toml --offline
athena native
```

Build once after native Rust changes; the normal launch is then simply
`athena native`.

Owl is the default Buddy; use `--mascot cat`, `--mascot bot`, or
`--mascot off` for a temporary override. The native bridge is a local Unix
socket and carries no credentials. Run the headless, input, exact-window
visual, and rendering checks from the repository root with
`scripts/native-smoke`, `scripts/native-input-smoke`,
`scripts/native-visual-smoke`, and `scripts/bench-rendering --require-native`.
The visual smoke covers the 1672×941, 1920×1080, 1280×800, 1280×720, and
1170×659 layout matrix, a same-process live resize sequence through those
sizes, and 27 exact-window fixtures (idle, short typing, 80+ character typing
with cursor movement, search, read, code, test, approval, and failure ×
owl/cat/bot) and validates
the metric-derived layout through `athena-terminal --dump-layout` before any
Xvfb capture, and validates `ATHENA_NATIVE_LAYOUT_DUMP` plus the 384×256
`ATHENA_NATIVE_OI_DUMP` generated by the live renderer. Set
`NATIVE_VISUAL_GOLDEN_DIR` to enforce reviewed ImageMagick
RMSE goldens, or pair it with `NATIVE_VISUAL_UPDATE_GOLDENS=1` to refresh
them intentionally after visual review.

Every visual run also compares the deterministic physical cabinet capture at
1672×941 against `assets/athenabox/cabinet-golden.png`. To intentionally
refresh that reviewed baseline, use
`NATIVE_CABINET_UPDATE_GOLDEN=1 scripts/native-cabinet-golden` and inspect the
result before committing it. `--cabinet-only` is the corresponding renderer
mode for deterministic physical-shell evidence.

The native renderer is split by ownership: `render/frame.rs` composes dirty
regions, `render/chassis.rs` draws the AthenaBOX shell and controls using the
bundled `assets/athenabox/chassis_noise.ppm` material,
`render/oi.rs` renders the semantic 384×256 OI target, `render/terminal.rs`
draws Alacritty cells, `render/prompt.rs` draws the lower instrument,
`render/buddy.rs` supplies equal-coverage sprites, `render/text.rs` owns Xft
font roles and width caching, and `render/primitives.rs` owns shared geometry
and CRT clipping. `platform/input_method.rs` and `platform/clipboard.rs` own
XIM and selection transport; `x11.rs` is the remaining
platform/event/lifecycle boundary and no longer contains the renderers.
Shared Buddy pose vocabulary and the three distinct sprite sets live under
`buddy/{poses,owl,cat,bot}.rs`.

`athena chat` is not the native window; it selects a host-terminal surface.
Use `--no-animations` or `--reduced-motion` for deterministic/static OI
presentation.

For the current hosted paths, use:

```text
athena --display glass   # hosted raster OI, confirmed Kitty transport
athena --display ansi    # universal instrument fallback
athena --display plain   # line-oriented fallback
```

The native work remains separate from hosted Glass. Kitty and WezTerm are
compatible hosts for the Python renderer, while this frontend owns its window
and compositor instead of asking another terminal to interpret graphics
escapes. `athena native` launches a Python service session as the PTY child and
connects its canonical event projection through a Unix socket; set
`ATHENA_NATIVE_BIN` when the binary lives outside the development tree.
